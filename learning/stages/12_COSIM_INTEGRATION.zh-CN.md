# 阶段十二：从独立模型进入联合仿真

[总路线](../QEMU_LEARNING_DESIGN.zh-CN.md) · [上一阶段](11_SYSTEMC_TLM_FOUNDATIONS.zh-CN.md) · [分页与 Linux 支线](13_MMU_AND_LINUX.zh-CN.md)

## 1. 本章交付边界

**实验目标：** 在完成前置实验后，按 MMIO、IRQ、DMA、时间协调的顺序实施本地联合仿真，为每个里程碑保存功能、故障与事件顺序证据，并分别验收功能模式和时间模式。

这是实施练习与进入条件，不是已经存在的桥接功能。与 [ESL 设计文档](../QEMU_SYSTEMC_ESL_DESIGN.zh-CN.md) 配合使用，全部限定为个人本地研究。不能执行虚构的 `-device systemc-bridge` 命令。实际状态见[验证记录](../VALIDATION.zh-CN.md)。

桥接开发需要独立估时；前六阶段的八周不包括本章。先完成七～十一阶段并提交自己的证据报告，再选择复用框架或自建桥。

## 2. 平台冻结表

在实验目录保存 `platform.md`，填写：

| 字段 | 首版选择/要填写的内容 |
| --- | --- |
| QEMU | 精确提交、构建参数、本地 diff |
| CPU / board | RV64 virt、单 vCPU、TCG、固定中断控制器 |
| SystemC | 版本、C++ 标准、时间分辨率 |
| Guest | 裸机 ELF 与校验值；后续再接 Linux |
| MMIO / IRQ | 从板级地址与中断表核对后分配，不能猜空闲范围 |
| 内存 | QEMU 持有 RAM；首版消息 DMA、不启用 IOMMU |
| 精度 | 先功能模式 F；通过时间验证后才启用模式 T |
| 退出范围 | 暂不支持联合快照、迁移和共享可执行 RAM |

如果选择 Remote-Port，先固定匹配的 QEMU 与 SystemC 两端提交并复现其支持的平台。不能把示例在其他板上成功等同于当前 virt 已有适配。

## 3. 一次只接通一条路径

| 步骤 | 输入与操作 | 必须留下的证据 | 失败后回退位置 |
| --- | --- | --- | --- |
| P1 独立模型 | 按阶段十一扩展寄存器、任务和内存目标 | 正常、错误、复位测试 | SystemC 本地模型 |
| P2 MMIO | Guest 读 ID、写读一个寄存器 | Guest 值、QEMU 回调、消息 ID、TLM 响应 | 协议编码或单端设备 |
| P3 IRQ | 模型置 DONE，Guest 服务并清除 | 拉高、trap、原因清除、拉低 | 阶段七中断链 |
| P4 DMA | 拷贝 16 字节，再扩大长度 | 源/目的逐字、数据先于 DONE/IRQ | 阶段九单端 DMA |
| P5 时间 | 先定时完成，再 WFI，再并发输入 | 授权、事件时刻、实际提交时刻 | 时间协调器 |
| P6 优化 | 测量后改批量或共享内存 | 功能与事件顺序回归、收益 | 未优化基线 |

P2 之前先在 QEMU 内部实现本地寄存器代理的最小实验版本，验证映射与复位，再把寄存器权威状态移至 SystemC。这个临时本地模型只用于隔离问题，最终不能两端同时维护一套设备状态。

## 4. 通信先验证进展能力

写协议表后，先用测试对端验证短读/短写、断连、立即响应、错误长度与事务 ID；不要直接用复杂模型作为唯一调试工具。请求与响应按 `(epoch, origin, transaction_id)` 匹配。

三种必须构造的交错：

1. Guest STATUS 读在途时，SystemC 发 DMA_READ；二者最终都完成。
2. 对端立即响应；等待表已建立，不丢失唤醒。
3. DMA 在途时复位；已提交 RAM 按规范保留，旧任务不得继续提交新写入。

分别画等待图和线程归属图。只有明确合法的服务上下文才能更新 QEMU 设备状态；“接收线程收到包”不是调用任意 DMA/IRQ API 的许可。

## 5. 时间模式的进入条件

先完成模式 F 的数据与顺序验证。模式 T 的前置包括：统一 tick、事件排序、执行边界、合法 lookahead、在途消息处理、WFI 空闲推进。

固定测试：输入 DMA 在 120 ns 采样、输出在 180 ns 提交、DONE/IRQ 在其后约定阶段生效。用专门允许并发观测的测试模型在提交前后读目标，验证未来数据不能提前出现。数值是测试规范，不是现实硬件参数。

再构造“已授予区间内出现更早 MMIO”和零 lookahead。必须说明为什么边界内没有未处理的更早输入；只减小量子、只交替运行两个进程，都不构成正确性证明。若没有这一依据，保持功能模式，不输出跨端时序结论。

## 6. 完成标准与报告

每一步至少留一条通过记录和一条故障定位记录。验收报告分列：功能结果、已验证事件顺序、模拟时间假设、墙钟开销、尚不支持的场景。

失败记录至少含：运行 ID、两端提交与版本、epoch、事务 ID、地址/长度、响应状态、双方模拟时间、授权边界、待处理队列。宿主墙钟仅用于超时诊断。

完成 P4 可以称“功能联合仿真跑通”；P5 的明确精度范围与边界条件全部验证后，才用于对应范围的时序分析。DMA 缓冲区共享、DMI、缓存一致性与 CPU 性能建模仍是独立扩展。
